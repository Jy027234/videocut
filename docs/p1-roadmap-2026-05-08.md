# P1.1 Manifest, Schema, and Docs Alignment

Date: 2026-05-08

## Scope

The P1 draft manifest adds a contract-only surface for the next adapter wave while keeping the P0 runtime stable:

- `audio.tts.generate_voiceover`
- `video.qc.generate_report`
- `video.qc.build_evidence_packet`
- `video.template.validate_remotion_template`
- `video.template.create_remotion_render_job`
- `video.render.export_project_format`

The P1 manifest extends the P0 manifest and keeps all new P1 capabilities disabled by default. The enabled capability set is still the P0 adapter set until the corresponding adapters, runtime gates, and Platform Core rollout policy are ready.

## Safety Defaults

P1.1 does not download models, run Chromium, or trigger voice cloning. Remotion entries describe validation and render-job contracts only; they do not execute a browser renderer. TTS voiceover accepts system or licensed synthetic voice profiles only. Clone voice, speaker diarization, face recognition, and person recognition remain deferred high-sensitivity capabilities that require explicit consent and platform approval before any default exposure.

## Schema Additions

`schemas/capability-io.schema.json` now includes P1 definitions for:

- voiceover input and output
- QC report input and output
- QC evidence packet input and output
- Remotion template validation input and output
- Remotion render-job input and output
- project export input and output

`schemas/artifact-manifests.schema.json` now includes P1 artifact manifest types for:

- `video_editing_toolkit.voiceover.v1`
- `video_editing_toolkit.qc_report.v1`
- `video_editing_toolkit.remotion_template_validation.v1`
- `video_editing_toolkit.remotion_render_job.v1`

## Platform Core Readiness

Platform Core can ingest the P1 manifest as a draft or disabled capability set without activating execution. A later rollout should only enable each P1 capability after its adapter contract, resource controls, consent policy, and artifact retention behavior pass integration tests.

## P1.2 TTS Runtime Preflight

`audio.tts.generate_voiceover` now accepts `synthesis_mode: preflight_only` or `preflight_only: true` to validate local readiness without downloading models, accessing the network, enabling ONNX execution, or synthesizing audio. The preflight checks whether `onnxruntime` is importable with `CPUExecutionProvider`, and whether caller-provided or environment-provided MOSS-TTS-Nano TTS and codec bundles contain the required local files.

The default local model root expects the upstream ONNX bundle layout:

- `MOSS-TTS-Nano-100M-ONNX`
- `MOSS-Audio-Tokenizer-Nano-ONNX`

The response exposes a caller-safe `runtime_preflight` object with `status`, `reason_code`, individual `checks`, and a `bundle_summary`. Local filesystem paths are intentionally omitted from public output. `model_runtime.execution_enabled` remains `false`, and voice clone requests remain deferred before preflight runs.

## P1.2 QC and Remotion Preflights

`video.qc.generate_report` now includes production evidence checks for media integrity, delivery-profile fit, audio loudness, and visual sampling. These checks consume caller-safe probe and quality evidence only; they do not run FFmpeg, OpenCV, or local filesystem reads.

`video.template.create_remotion_render_job` now includes dispatcher readiness checks for Node.js, Chromium, Remotion runtime availability, license confirmation, sandbox policy, and network policy. These checks consume caller-provided dispatcher metadata only; they do not run Node, Chromium, or Remotion.

## Remaining Gates

1. Promote capabilities one by one from `disabled` to `enabled` only after Platform Core routing, approval policy, and resource limits are wired.
2. Implement real MOSS-TTS-Nano ONNX CPU execution after model bundle staging, licensing, cache, and artifact retention policy are approved.
3. Connect Remotion to an isolated Node/Chromium dispatcher only after commercial licensing, sandbox policy, and dispatcher readiness checks are satisfied.
4. Keep diarization, face/person recognition, and clone voice deferred until high-sensitivity approval and audit flows are implemented.

## High-Sensitivity Gate Contract

`src/video_editing_toolkit/security.py` provides a pure, caller-safe gate for deferred high-sensitivity capabilities:

- `audio.tts.clone_voice`
- `audio.speech.diarize_speakers`
- `video.analysis.recognize_faces`
- `video.analysis.recognize_people`

The gate reports `deferred`, `blocked`, or `approved_for_preflight_only` with required and missing approval fields, fixed retention notes, and fixed audit requirements. It never approves execution and never echoes approval values, local paths, provider tokens, voiceprints, or recognition evidence into caller-visible output.

## P1.3 Project Export and QC Evidence Contracts

`video.qc.build_evidence_packet` now produces a caller-safe evidence packet from supplied probe, audio, visual, timeline, subtitle, brand, and delivery evidence. It can materialize `qc_evidence_packet.json` through the artifact store, while omitting local paths, storage URIs, and signed download tokens from public responses.

`video.render.export_project_format` now produces a contract-only FCPXML interchange document from a declarative timeline or composition plan. It does not invoke DaVinci Resolve, Final Cut Pro, shell commands, or local app automation. The route is P1 experimental only and remains disabled in the manifest until Platform Core explicitly enables the rollout.
