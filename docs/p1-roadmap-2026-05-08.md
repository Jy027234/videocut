# P1 Manifest, Schema, and Docs Alignment

Date: 2026-05-08

## Scope

The P1 draft manifest adds a contract-first surface for the next adapter wave while keeping the P0 runtime stable:

- `audio.tts.generate_voiceover`
- `video.qc.generate_report`
- `video.qc.build_evidence_packet`
- `video.qc.plan_media_inspection`
- `video.qc.generate_media_inspection_evidence`
- `video.template.validate_remotion_template`
- `video.template.create_remotion_render_job`
- `video.render.export_project_format`

The P1 manifest extends the P0 manifest and keeps all new P1 capabilities disabled by default. The enabled capability set is still the P0 adapter set until the corresponding adapters, runtime gates, and Platform Core rollout policy are ready.

## Safety Defaults

P1.1 does not download models, run Chromium, or trigger voice cloning. Remotion entries describe validation and render-job contracts only; they do not execute a browser renderer. TTS voiceover accepts system or licensed synthetic voice profiles only. Clone voice, speaker diarization, face recognition, and person recognition remain deferred high-sensitivity capabilities that require explicit consent and platform approval before any default exposure.

## Platform Core Readiness

Platform Core can ingest the P1 manifest as a draft or disabled capability set without activating execution. A later rollout should only enable each P1 capability after its adapter contract, resource controls, consent policy, and artifact retention behavior pass integration tests.

The next Platform Core platformization metadata contracts are documented in `docs/platform-core-platformization.md`; they are metadata-only, review-only, preserve P1 disabled status, and do not mutate Platform Core network state or repositories.

## P1.2 TTS Runtime Preflight

`audio.tts.generate_voiceover` now accepts `synthesis_mode: preflight_only` or `preflight_only: true` to validate local readiness without downloading models, accessing the network, enabling ONNX execution, or synthesizing audio. The preflight checks whether `onnxruntime` is importable with `CPUExecutionProvider`, and whether caller-provided or environment-provided MOSS-TTS-Nano TTS and codec bundles contain the required local files.

The default local model root expects the upstream ONNX bundle layout:

- `MOSS-TTS-Nano-100M-ONNX`
- `MOSS-Audio-Tokenizer-Nano-ONNX`

The response exposes a caller-safe `runtime_preflight` object with `status`, `reason_code`, individual `checks`, and a `bundle_summary`. Local filesystem paths are intentionally omitted from public output. `model_runtime.execution_enabled` remains `false`, and voice clone requests remain deferred before preflight runs.

These checks consume caller-provided dispatcher metadata only; they do not run Node, Chromium, or Remotion.

## High-Sensitivity Gate Contract

`src/video_editing_toolkit/security.py` provides a pure, caller-safe gate for deferred high-sensitivity capabilities:

- `audio.tts.clone_voice`
- `audio.speech.diarize_speakers`
- `video.analysis.recognize_faces`
- `video.analysis.recognize_people`

The gate reports `deferred`, `blocked`, or `approved_for_preflight_only` with required and missing approval fields, fixed retention notes, and fixed audit requirements. It never approves execution and never echoes approval values, local paths, provider tokens, voiceprints, or recognition evidence into caller-visible output.

## P1.4 Platform Core Platformization Contracts

`video_editing_toolkit.platform_core` now emits three review-only metadata payloads for future Platform Core ingestion:

- `platform_core_toolkit_onboarding_bundle.v0`
- `platform_core_learning_audit_event.v0`
- `platform_core_release_dossier.v0`

These payloads preserve manifest status, keep P1 capabilities outside the default P0 route table, omit storage locators and signed artifact links from audit events, and mark Release Center publication as `no_go` until Platform Core performs an explicit product-side rollout. The local CLI can print the payloads, but it does not publish, ingest, register, or mutate Platform Core state.

`agentctl` also has a regression guard proving P1 experimental capabilities are rejected by default through the P0 runtime path with no output artifacts and no caller-visible token, storage, or URL leakage.

## P1.5 QC Media Inspection Plan

`video.qc.plan_media_inspection` is now a disabled-by-default P1 experimental capability for planning production media evidence generation. It emits a caller-safe `media_inspection_plan` with required evidence, planned checks, skipped runtime operations, and zero runtime invocation counts.

This remains plan-only: it does not fetch media, materialize artifact bytes, run binary probes, sample frames, execute audio or visual analysis, return local paths, or expose storage locators and signed artifact links. The external worker policy now rejects every P1 capability with `worker.p1_capability_disabled` before artifact materialization, making the default boundary explicit.

## P1.6 Dispatcher Attestation and Execution Guards

Remotion render jobs now accept a typed `dispatcher_preflight_attestation` contract. The attestation records Node.js, Chromium, Remotion, sandbox, network, license, and execution posture without exposing endpoints, tokens, paths, Chromium binaries, or raw commands. The adapter consumes it as `dispatcher_attestation` readiness evidence, but still does not run Node, Chromium, or Remotion.

TTS now has an explicit regression guard proving that a configured local `model_path` does not trigger ONNX runtime import or synthesis. The adapter still returns `tts.onnx_runtime_not_enabled` with `execution_enabled=false` and no audio artifact until a separate execution contract is approved.

The worker and manifest tests now assert that every P1 route exactly matches disabled P1 manifest capabilities and every P1 capability is rejected before artifact materialization by the default worker path.

## P1.8 Local Loop Runner and Deployment Hardening

P1.8 adds an explicit Platform Core local loop runner. The default runner output is `platform_core_local_loop_runner_preview.v0`, which is no-mutation and does not call agentctl or Platform Core. Only `--execute-local-loop` performs the local sequence: manifest registration dry-run, RunSpec enqueue, worker heartbeat/lease/execute/complete, Platform Core completion normalization, and learning/audit metadata preview.

The runner separates the agentctl control-plane URL from the Platform Core artifact-byte URL. This keeps video processing in the external worker while preserving Platform Core as the future artifact authorization and byte service boundary.

Docker Compose now declares separate `cpu_light`, `cpu_heavy`, `analysis`, `speech`, and `render` worker profiles with explicit resource guard environment variables, artifact cache volume, and no secret defaults. The default `toolkit` service remains lightweight.

`LocalArtifactStore` now writes caller-safe artifact manifests, exposes metadata summaries, and can clean up expired local artifacts by `expires_at` or retention policy TTL. Cleanup summaries return counts and artifact ids only; they do not expose local paths, storage URIs, download URLs, or signed tokens.

P1.8 still does not enable disabled P1 capabilities, publish to Platform Core, or modify the Platform Core repository.

## P1.9 QC Media Inspection Evidence

`video.qc.generate_media_inspection_evidence` adds a disabled-by-default P1 experimental contract for producing production media inspection evidence under controlled worker execution. The output schema requires `media_inspection_evidence`, `qc_media_inspection_evidence_artifact_ref`, and `artifact_refs`, and those artifact refs are caller-safe only: no local paths, raw commands, storage locators, or signed download URLs.

The manifest keeps P1.9 disabled and records the controlled execution posture in both the top-level P1.9 sandbox policy and the capability sandbox policy: `controlled_worker_execution`, explicit policy opt-in, `artifact_ref_only`, `network_access=disabled_by_default`, `platform_core_repository_mutation=false`, `return_local_paths=false`, and `allow_raw_command=false`. `video.qc.plan_media_inspection` remains plan-only and does not gain media fetch, FFmpeg, OpenCV, audio, visual, or artifact materialization execution.

## P1.10 Local Controlled Execution Loop

P1.10 adds tests and manifest/docs alignment for an explicit local-only P1 execution loop. Product defaults do not change: P1 capabilities still reject through the default local `agentctl` path and the default external worker policy before artifact materialization, and they do not create output artifacts.

The only supported P1.10 execution path is an operator-controlled local worker with an explicit `allowed_p1_capabilities` allowlist, matching `VIDEO_TOOLKIT_ALLOWED_P1_CAPABILITIES` / `--allowed-p1-capabilities` for CLI and env configuration. When `video.qc.generate_media_inspection_evidence` is allowlisted and the request policy includes `allow_p1_qc_media_inspection_execution=true`, the worker may materialize input artifact refs into the local artifact store and call the local `run_agentctl` runner. Outputs remain caller-safe artifact refs only.

This is not Platform Core product enablement, Tool Catalog publication, Release Center approval, or a default P1 rollout. Network access remains disabled by default, raw commands and local paths remain non-public, and Platform Core repository mutation remains out of scope.

## P1.12 Repeatable Local QC Smoke Runner

P1.12 turns the manual P1.11 smoke into a reusable local command:
`video-toolkit-p1-qc-smoke`. The command accepts a local source video, stores it
as a local `source_video` artifact, calls `run_agentctl` with
`video.qc.generate_media_inspection_evidence` explicitly allowlisted, sets
`allow_p1_qc_media_inspection_execution=true` for that request, and returns a
compact caller-safe summary.

`--result-json` writes a reusable smoke artifact that contains the compact
summary plus the local agentctl response. The JSON omits local filesystem paths,
worker paths, storage URIs, raw commands, and signed download tokens. The CLI
also supports `--use-static-ffmpeg`, which scopes
`VIDEO_TOOLKIT_USE_STATIC_FFMPEG=1` to that process and then restores the
previous environment value.

This remains a local integration rehearsal, not Platform Core product
enablement. Default P1 routes are still disabled unless the controlled local
runner supplies the allowlist and the request-level policy opt-in.

## P1.13 Platform Core QC Smoke Rehearsal

P1.13 adds `platform_core_p1_qc_smoke_rehearsal.v0`, a no-mutation wrapper for a
completed P1 QC smoke result. The Platform Core CLI accepts
`--p1-qc-smoke-rehearsal-json` and converts the local smoke result into a
Platform Core request preview, agentctl envelope preview, normalized completion,
learning/audit metadata preview, and quality gate.

This wrapper does not execute media analysis, enqueue RunSpecs, call Platform
Core, write to the Platform Core repository, or enable disabled P1 routes. It
also removes local artifact download handles from the rehearsal payload so the
result is suitable for review logs and release dossiers.

The QC quality gate is `passed` only when the smoke result is successful, the
evidence summary is `ready`, and `media_probe`, `audio_quality`, and
`visual_quality` all passed. Any partial or failed smoke remains `needs_review`.

P1.13 also adds agentctl regression coverage for non-executing P1 capabilities
under explicit allowlist registration: MOSS-TTS-Nano remains `plan_only`,
Remotion remains dispatcher-owned with `runtime_execution=not_started`, and
FCPXML export remains contract-only with no DaVinci, Final Cut Pro, shell, Node,
Chromium, ONNX, or local app execution.
