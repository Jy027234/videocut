# P1.1 Manifest, Schema, and Docs Alignment

Date: 2026-05-08

## Scope

P1.1 adds a contract-only surface for the next adapter wave while keeping the P0 runtime stable:

- `audio.tts.generate_voiceover`
- `video.qc.generate_report`
- `video.template.validate_remotion_template`
- `video.template.create_remotion_render_job`

The P1 manifest extends the P0 manifest and keeps all new P1.1 capabilities disabled by default. The enabled capability set is still the P0 adapter set until the corresponding adapters, runtime gates, and Platform Core rollout policy are ready.

## Safety Defaults

P1.1 does not download models, run Chromium, or trigger voice cloning. Remotion entries describe validation and render-job contracts only; they do not execute a browser renderer. TTS voiceover accepts system or licensed synthetic voice profiles only. Clone voice, speaker diarization, face recognition, and person recognition remain deferred high-sensitivity capabilities that require explicit consent and platform approval before any default exposure.

## Schema Additions

`schemas/capability-io.schema.json` now includes P1 definitions for:

- voiceover input and output
- QC report input and output
- Remotion template validation input and output
- Remotion render-job input and output

`schemas/artifact-manifests.schema.json` now includes P1 artifact manifest types for:

- `video_editing_toolkit.voiceover.v1`
- `video_editing_toolkit.qc_report.v1`
- `video_editing_toolkit.remotion_template_validation.v1`
- `video_editing_toolkit.remotion_render_job.v1`

## Platform Core Readiness

Platform Core can ingest the P1 manifest as a draft or disabled capability set without activating execution. A later rollout should only enable each P1 capability after its adapter contract, resource controls, consent policy, and artifact retention behavior pass integration tests.
